## Русский

### Что это
Работающий MVP цифрового двойника сборочной линии автозавода. Он показывает состояние цехов и оборудования почти в реальном времени, считает KPI, фиксирует инциденты и с помощью ИИ прогнозирует отказы оборудования, выпуск смены и узкие места. Интерфейс переключается между русским и корейским языками.

| Требование кейса | Реализация |
|---|---|
| Визуализация участков и оборудования | Интерактивная схема 5 цехов / 15 участков: состояние, буферы, склад, анимация потока |
| Мониторинг KPI (производительность, загрузка, простои, качество) | Выпуск/план, JPH, OEE линии и участков, загрузка, простои по причинам, FPY, НЗП |
| Инциденты и отклонения | Аварии, нехватка комплектующих, срыв поставки, рост брака, ИИ-предупреждения, риск плана |
| Аналитическая панель руководителя | Выпуск vs план, потери по участкам, Парето дефектов, узкие места, запасы |
| Прогноз простоев и узких мест (ИИ) | Индекс здоровья, риск отказа на 4 ч, Монте-Карло прогноз смены, what-if рекомендации ТО |
| Тестовые данные организаторов | Вкладка «Данные АЛЛЮР»: OEE, брак, простои и план по целевым показателям (OEE ≥ 85 %, брак ≤ 2 %, простой ≤ 60 мин/сутки, ≥ 5 500 авто/мес), загрузка своих CSV |

**Демо без установки:** https://erikalpysbaev30-source.github.io/hackathon-2026/demo/ (симулятор и облегчённая ИИ-модель работают в браузере).

### Быстрый старт
```bash
./run.sh            # установит зависимости и запустит сервер
# открыть http://localhost:8000
```
или Docker:
```bash
docker build -t allur-twin . && docker run -p 8000:8000 allur-twin
```
Модели ИИ лежат в `backend/models/`. Если их удалить, сервер переобучит их при старте (≈2 мин).

### Версия без сервера
`docs/demo/index.html` — тот же интерфейс одним файлом: симулятор и ИИ-модель (облегчённая, логистическая регрессия) работают прямо в браузере. Достаточно открыть файл. Чтобы опубликовать в интернете, включите GitHub Pages (Settings → Pages → ветка `main`, папка `/docs`): сайт откроется по адресу https://erikalpysbaev30-source.github.io/hackathon-2026/demo/. Пересборка: `python scripts/build_static.py`.

### Демонстрация (кнопки на вкладке «Цех онлайн»)
1. **Авария робота W3**: участок краснеет, появляется инцидент, перед W3 копятся кузова, прогноз смены падает.
2. **Задержка поставки двигателей**: запас падает, затем A2 останавливается («нет комплектующих»).
3. **Брак в окрасочной камере**: растёт доработка, падает FPY, на Парето видно «подтёки ЛКП».
4. **Скрытый износ узла A2**: участок ещё работает, но ИИ поднимает риск отказа и рекомендует ТО с расчётом эффекта.

Скорость времени: ×1 … ×900 (по умолчанию 1 секунда = 1 минута завода).

### Архитектура
```
Источники (MES/1С, SCADA/ПЛК OPC UA, IoT MQTT, ТОиР, WMS)
   → шлюз интеграции (POST /api/telemetry, адаптеры)
   → ядро двойника (модель завода, KPI/OEE, инциденты, история)
   → ИИ-сервисы (индекс здоровья, риск отказа, Монте-Карло прогноз, what-if)
   → API (REST + WebSocket) → веб-интерфейс RU/KO
```
* `backend/app/simulator.py`: дискретная модель линии (участки, буферы, склад, износ, датчики, брак). В MVP она заменяет реальные данные; в пилоте её место займут потоки MES/SCADA.
* `backend/app/ml.py`: индекс здоровья (регрессия), риск отказа на 4 ч (градиентный бустинг), Монте-Карло прогноз смены, рекомендации what-if.
* `backend/app/incidents.py`: движок инцидентов.
* `backend/app/main.py`: FastAPI, WebSocket, сценарии, интеграционный endpoint.
* `frontend/`: интерфейс (vanilla JS + Chart.js), без сборки.
* `scripts/evaluate_effect.py`: расчёт бизнес-эффекта (реактивное vs предиктивное ТО).
* `backend/app/testdata.py`: загрузка тестовых данных АЛЛЮР и проверка по целевым показателям; `scripts/build_allur_data.py` собирает их для интерфейса.
* `scripts/train_lite.py`: облегчённая модель для браузерной версии.

### API
| Метод | Путь | Назначение |
|---|---|---|
| WS | `/ws` | снимок состояния каждую секунду |
| GET | `/api/state`, `/api/history`, `/api/station/{id}` | состояние, история KPI, детали участка |
| POST | `/api/scenario/{robot_failure\|supply_delay\|paint_quality\|wear\|reset}` | демо-сценарии |
| POST | `/api/maintenance/{id}` | назначить ТО |
| POST | `/api/telemetry` | приём реальных показаний датчиков `{station, vibration, temperature, current}` |
| GET | `/api/metrics`, `/api/export.csv` | качество модели и эффект, экспорт истории |

### Данные АЛЛЮР и калибровка
Тестовые данные организаторов лежат в `data/allur_test_data/` (CSV). Что из них следует (`python -m app.testdata` из папки `backend/`):
* OEE линий 87,6–99,2 % — норма ≥ 85 % выполнена, ближе всего к границе Сварка-1 02.10.
* Брак выше нормы 2 % в 3 из 6 замеров: Окраска 3,5 % и 5,2 %, Сварка 2,7 % (02.10).
* Простой Конвейер-03 55 мин при лимите 60 мин в сутки.
* План по моделям 4 800 авто меньше цели 5 500; темп 120 авто/смену × 2 смены × 22 дня = 5 280 (22 рабочих дня — наше допущение).
* Время работы линий и журнал простоев расходятся в 3 из 6 записей.

Модель линии (`backend/config/plant.json`) откалибрована по этим данным: план 120 авто/смену, 2 смены по 8 ч (ночные часы пропускаются), модели Onix / Cobalt / JAC J7, оборудование ABB-01…04, Камера-01/02, Конвейер-01…03, уровень брака по участкам как в данных, длительность ремонтов 15–70 мин, причины простоев как в журнале. На этой модели переобучены ИИ (`python -m app.ml`, ROC-AUC 0,84) и пересчитан эффект (`python scripts/evaluate_effect.py 10 4 0.35`). Двойник открывает инцидент, когда простой оборудования за сутки приближается к 60 мин или превышает их.

Подробной истории датчиков организаторы не дали, поэтому сигналы датчиков генерирует симулятор. Реальные показания подключаются через `/api/telemetry`, после чего модели переобучаются тем же конвейером.

## 한국어

### 개요
자동차 공장 조립 라인의 디지털 트윈 MVP입니다. 공장과 설비 상태를 거의 실시간으로 보여 주고, KPI를 계산하며, 이상을 자동으로 감지합니다. AI가 설비 고장, 교대 생산량, 병목 공정을 예측합니다. 인터페이스는 러시아어와 한국어를 지원합니다.

### 실행
```bash
./run.sh     # http://localhost:8000
```

### 서버 없는 버전
`docs/demo/index.html` 파일 하나로 시뮬레이터와 경량 AI 모델이 브라우저에서 실행됩니다. GitHub Pages(`/docs` 폴더)로 공개할 수 있습니다.

### 데모 시나리오 ("실시간 공장" 탭)
1. **W3 로봇 고장**: 공정이 빨간색으로 바뀌고 사고가 생성되며, 교대 예측이 하락합니다.
2. **엔진 납품 지연**: 재고가 줄어들고 A2가 "부품 부족"으로 정지합니다.
3. **도장 부스 품질 이상**: 수정 작업이 늘고 직행률(FPY)이 떨어집니다.
4. **A2 설비 숨은 마모**: 공정은 가동 중이지만 AI가 고장 위험을 높이고 효과 계산과 함께 정비를 권고합니다.

### 아키텍처
데이터 소스(MES/1C, SCADA/PLC, IoT, CMMS, WMS) → 연동 게이트웨이 → 트윈 코어(공장 모델, KPI/OEE, 사고 엔진) → AI 서비스(건강 지수, 4시간 고장 위험, 몬테카를로 예측, What-if) → REST/WebSocket API → 웹 인터페이스(RU/KO).

### ALLUR 데이터
주최 측 테스트 데이터는 `data/allur_test_data/`에 있으며 "ALLUR 데이터" 탭에서 목표 지표(OEE ≥ 85%, 불량 ≤ 2%, 일일 정지 ≤ 60분, 월 5,500대 이상)로 점검합니다. 결과: 모든 라인 OEE 기준 충족, 도장 불량률 3.5%·5.2%와 용접 2.7%는 기준 초과, 컨베이어-03 정지 55분(한도 60분), 모델별 계획 합계 4,800대로 목표보다 700대 부족. 라인 모델은 이 데이터(교대당 120대, 2교대, 공정별 불량률, 설비명)로 보정했고, AI 모델도 다시 학습했습니다. 센서 이력은 제공되지 않아 시뮬레이터가 생성하며, 실제 센서는 `/api/telemetry`로 연동합니다.
